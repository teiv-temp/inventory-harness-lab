# 프로젝트 SSOT

> 책임별 원본과 원본 간 판단 원칙을 등록한다. 각 규칙의 상세 내용은 질문별 원본에 둔다.

## 0. 책임별 SSOT

| SSOT | 책임 |
|---|---|
| SSOT 1 — 요구사항 | 이 프로그램은 무엇을 해야 하는가 |
| SSOT 2 — 아키텍처 | 어떤 구조와 경계를 지켜야 하는가 |
| SSOT 3 — 하네스 운영 규칙 | 검증과 구현·검증 절차를 어떻게 운영하는가 |
| SSOT 4 — 이번 작업 계약 | 이번 Issue에서 무엇을 바꾸는가 |

현재 등록된 GitHub Issue가 없으면 SSOT 4는 `Issue 미지정`이다. PR·커밋은 Issue를 대체하지 않는다.

## 2. 보호 경계와 권한

Protected 보호 경로는 사람이 소유하는 정책·지침 영역이다.

- `docs/01-requirements.md`
- `docs/06-architecture.md`
- `docs/harness/`
- `AGENTS.md`
- `CLAUDE.md`

애플리케이션 코드와 Issue별 테스트는 Issue 범위 안에서 AI가 수정할 수 있다. 보호 경로를 수정해야 하면 사람에게 대상·범위·사유를 먼저 제시하고, 명시적으로 허용된 범위 안에서만 수정한다. AI는 보호 경로의 정책을 임의로 확정하거나 범위를 넓히지 않는다.

보호 경로 변경의 승인 방식·현재 head 검증·사람 승인 원칙은 이 문서의 보호정책과 실행 구현을 따른다. 사람이 직접 변경 결과를 검토하고 승인하기 전에는 보호 경로 변경을 완료로 선언하지 않는다.

## 3. 충돌과 원본 변경 원칙

1. 참고 문서와 SSOT가 충돌하면 SSOT를 따른다.
2. Issue와 SSOT 또는 SSOT끼리 충돌하면 AI가 임의로 선택하지 않는다.
3. 충돌 범위의 구현·문서 수정·데이터 변경·완료 선언은 사람의 결정 전까지 보류한다.
4. 원본이 없거나 판단 근거가 부족하면 추측으로 보완하지 않고 사람에게 판단을 요청한다.
5. 한 책임의 규칙은 해당 원본에만 기록하고 다른 문서에는 복제하지 않는다.
6. 사람이 원본 수정을 명시적으로 요청해도 요청에 없는 정책·예외·우선순위는 추가하지 않는다.

### 보호된 원본 수정 요청 기록

보호된 원본을 수정하기 전 다음 정보를 확인한다.

```text
Target: <대상 파일 또는 절>
Scope: <허용된 변경 범위>
Reason: <변경 사유>
Requested-By: human
```

이 기록은 AI의 수정 허용 범위를 정하는 입력이며, Protected의 최종 승인 기록을 대체하지 않는다. 항목이 없거나 모호하면 수정하지 않는다. `NEEDS_HUMAN`의 상태·보고·사람 처분·재개는 [`03-loop.md`](03-loop.md)를 따른다.

## 4. 기본값

유지보수 Issue의 구현 루프 최대 횟수 기본값은 **3회**다. Issue에 작업별 값이 있으면 그 값을 사용하고, 반복 절차·판정 후속 처리·사람 개입은 [`03-loop.md`](03-loop.md)를 따른다.

보호된 원본을 수정하기 전에는 사람이 대상·범위·사유를 명시한다. 요청 기록이 없거나 모호하면 AI는 수정하지 않는다.

```text
Target: <대상>
Scope: <허용 범위>
Reason: <변경 사유>
Requested-By: human
```

이 기록은 수정 요청의 근거이며, 최종 승인 기록을 대체하지 않는다.
